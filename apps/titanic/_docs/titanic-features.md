# 타이타닉 데이터셋 분석 및 피처 엔지니어링 가이드 (Titanic Dataset Guide)

이 문서는 클로드(Claude)와 같은 대형 언어 모델(LLM)이 타이타닉 생존자 예측 데이터셋의 구조를 완벽히 이해하고, 효과적인 피처 엔지니어링(Feature Engineering)을 수행할 수 있도록 최적화된 한글 안내서입니다.

---

## 1. 데이터셋 개요 (Overview)

타이타닉 데이터셋은 침몰 사고에서 어떤 승객들이 생존했는지 예측하는 머신러닝의 클래식한 분류(Classification) 문제입니다. 데이터는 크게 두 개의 그룹으로 나뉩니다.

* **학습 데이터셋 (`train.csv`)**: 머신러닝 모델을 학습시키는 데 사용됩니다. 각 승객의 생존 여부(정답 레이블 또는 Ground Truth)가 포함되어 있습니다.
* **테스트 데이터셋 (`test.csv`)**: 학습된 모델의 성능을 검증하는 데 사용됩니다. 생존 여부가 제공되지 않으며, 모델을 통해 이를 예측해야 합니다.
* **제출 샘플 파일 (`gender_submission.csv`)**: "여성 승객은 모두 생존하고, 남성 승객은 모두 사망했다"는 가정 하에 작성된 기본 예측 예시 파일입니다. 제출 양식(PassengerId, Survived)을 확인할 때 참고합니다.

---

## 2. 데이터 사전 (Data Dictionary)

데이터셋을 구성하는 각 변수(Feature)의 정의와 타입, 범주형 데이터의 키 값은 다음과 같습니다.

| 변수명 (Variable) | 정의 (Definition) | 키 값 설명 (Keys / Values) | 데이터 타입 |
| :--- | :--- | :--- | :--- |
| **survival** | 생존 여부 | 0 = 사망 (No), 1 = 생존 (Yes) | 범주형 (이진 변수) |
| **pclass** | 티켓 등급 (사회·경제적 지위) | 1 = 1등석 (상류층), 2 = 2등석 (중산층), 3 = 3등석 (하류층) | 범주형 (순서형) |
| **sex** | 성별 | male = 남성, female = 여성 | 범주형 (명목형) |
| **age** | 나이 (단위: 세) | 1세 미만은 소수점 표시. 추정 나이는 `xx.5` 형태 | 수치형 (연속형) |
| **sibsp** | 동반한 형제자매 / 배우자의 수 | 형제, 자매, 의붓형제, 의붓자매, 남편, 아내 포함 | 수치형 (이산형) |
| **parch** | 동반한 부모 / 자녀의 수 | 어머니, 아버지, 아들, 딸, 의붓아들, 의붓딸 포함 | 수치형 (이산형) |
| **ticket** | 티켓 번호 | 알파벳 및 숫자 조합의 고유 문자열 | 문자형 |
| **fare** | 여객 운임 (티켓 가격) | 승객이 지불한 비용 | 수치형 (연속형) |
| **cabin** | 객실 번호 | 선실 구역 및 번호 (예: C85, E46) | 문자형 |
| **embarked** | 승선 항구 | C = 셰르부르 (Cherbourg)<br>Q = 퀸즈타운 (Queenstown)<br>S = 사우샘프턴 (Southampton) | 범주형 (명목형) |

## 3. 변수별 상세 특성 및 제약 사항 (Variable Notes)

피처 엔지니어링 시 LLM이 반드시 인지해야 할 도메인 지식과 제약 조건입니다.

* **pclass (사회·경제적 지위 프록시)**: 
    * 1등석은 구조 우선순위가 높았으며, 객실 위치가 갑판과 가까워 생존율이 가장 높았습니다. 반면 3등석은 선체 하부에 주로 위치하여 생존율이 매우 낮았습니다.
* **age (나이)**: 
    * 어린이(특히 영유아)는 '여성과 아이 먼저' 규칙에 따라 생존율이 높았습니다.
    * 결측치(Missing Value)가 다수 존재하므로, 단순히 평균값으로 채우기보다는 `pclass`나 `sex`, 혹은 호칭(Title)별 평균을 활용하는 변환이 필요합니다.
* **sibsp & parch (가족 관계 정의)**:
    * **Sibling (형제자매)**: 남동생, 여동생, 의붓형제, 의붓자매
    * **Spouse (배우자)**: 남편, 아내 (단, 약혼자 및 내연 관계는 제외됨)
    * **Parent (부모)**: 어머니, 아버지
    * **Child (자녀)**: 아들, 딸, 의붓아들, 의붓딸
    * *주의*: 부모 없이 유모(Nanny)와 함께 탑승한 아이들의 경우, 부모가 없으므로 `parch = 0`으로 기록되어 있습니다.

## 4. LLM을 위한 피처 엔지니어링 제안 및 아이디어

클로드가 이 데이터를 바탕으로 새로운 파생 변수를 생성할 때 영감을 줄 수 있는 가이드라인입니다.

### ① 가족 규모 (Family Size) 변수 생성
* `sibsp`와 `parch`를 더하고 본인(1)을 추가하여 `FamilySize` 변수를 생성할 수 있습니다.
    * `FamilySize = sibsp + parch + 1`
* 나아가 1인 탑승객 여부를 나타내는 이진 변수 `IsAlone` (FamilySize가 1이면 1, 아니면 0)을 유도할 수 있습니다. (동반자 유무에 따른 생존율 차이 반영)

### ② 이름(Name)에서 호칭(Title) 추출
* 승객 이름에는 `Mr.`, `Mrs.`, `Miss.`, `Master.` 등 사회적 신분이나 성별, 연령대를 나타내는 호칭이 포함되어 있습니다.
* 이 호칭을 정규표현식으로 추출하여 문자열 구조를 단순화하면, `age` 결측치를 더 정교하게 추정할 수 있으며 귀족/고위직(Dr, Rev, Col 등)의 생존 경향성도 포착할 수 있습니다.

### ③ Fare(운임)의 정규화 및 범주화
* 티켓 가격인 `fare`는 오른쪽으로 치우친(Skewed) 분포를 가질 확률이 높으므로 로그 변환(`log1p`)을 적용하거나, 등급별 밴드(FareBand)로 묶어 범주형 변수로 변환할 수 있습니다.
* 동일한 티켓 번호(`ticket`)를 가진 승객들이 운임을 나누어 냈는지 여부를 확인하여 '인당 운임'을 계산하는 것도 좋은 접근입니다.

### ④ Cabin(객실) 데이터의 첫 글자 추출
* `cabin` 변수는 결측치가 매우 많지만, 값이 존재하는 경우 첫 글자(알파벳)는 선박의 구역(Deck A~G)을 의미합니다. 구역별로 구명보트와의 거리 및 수면으로부터의 높이가 달랐기 때문에 생존율에 유의미한 영향을 미칩니다. 결측치는 'Unknown' 등으로 처리하여 별도 범주로 관리할 수 있습니다.
